# 课堂与 Lesson Pack 设计契约

状态：Milestone A 设计草案。接口名称说明概念，不是本次新增运行时 API 或数据库结构。

## 1. 从目标到可教学内容

课程图决定范围和关联；Lesson Pack 承载实际学习。一个 objective 可以拆成多课，一课也可以用支持目标，但题目证据须绑定实际检查的子技能。不能因为读完支持材料就给所有关联 objective 记成功。

一个 Pack 包含：

| 字段组 | 必须具备的内容 |
|---|---|
| 身份 | lessonId、version、level、主目标、支持目标、发布状态 |
| 来源 | syllabus/教材定位、核实状态、原创内容说明 |
| 入场 | 学生可读目标、前置小检查、失败后的微型补课 |
| 教学步骤 | 稳定 stepId、类型、原文/旁白、画面、操作、反馈及下一步 |
| 题目 | 稳定 itemId、数据关系、输入类型、答案规则、语义约束、提示及变式 |
| 教具 | 可信 renderer 类型、参数、可操作动作、文字等价物 |
| 帮助 | H1 注意线索、H2 表示/步骤支持、H3 完整示范、后续新题 |
| 结束 | 退出检查、局部学习小结、未完成/需要支持说明 |
| 恢复 | 版本固定、步骤与题目实例、草稿、帮助、提交状态 |
| 验收 | 正确、典型错误、非典型错误、暂停、断网、模型失败等场景 |

A 使用 Markdown 表达人工可审阅设计，不在这个阶段选择大型 CMS 或发布 schema。B 把这些字段转换成 TypeScript 可校验格式，并以 A 的真实内容检验接口，而不是先设计空泛 DSL。

## 2. 课堂主界面

顶栏：学生头像/昵称、课名、简短进度、暂停。中心：单一当前教学场景，数学表示和题目占主位。辅导区：短解释、一个当前问题、朗读/重播/提示入口。底部：提交、下一步、换种讲法。家长详细记录放在家长界面。

不同时展示所有未来题目和长对话；手机上内容在前、帮助在后，切换不得丢失输入。按钮默认产品目标至少 44×44 CSS px；这是本项目设计目标，不是本次做过的可访问性认证。所有拖放提供点击选择/键盘替代；颜色不是唯一线索；数字关系配标签，动画可跳过且有静态等价步骤。

朗读为逐条播放、可停可重播，不自动连续说话。英语题干和中文支持是课例基线，按选择只突出一种语言，翻译需保持同一题目数量、单位与问法。TTS 或模型不可用时，已编写的文字和示范继续可用。

## 3. 步骤模式与答案显示

| 模式 | 谁在做 | 答案策略 | 记录含义 |
|---|---|---|---|
| DEMO | 系统示范、学生观察或控制播放 | 允许完整展示解法 | viewed，不是答题成功 |
| GUIDED | 学生完成一部分，系统给脚手架 | 显示当前需要的支持 | guided/assisted |
| INDEPENDENT | 学生独立完成当前新题 | 隐藏答案；求助后可给提示 | 未求助首答与辅助重答分开 |
| EXIT_CHECK | 新题检查本课子技能 | 可选择求助，不无限锁住 | 局部证据，不直接认定整个目标掌握 |

客户端可以收到题干和作图所需已知量，不能收到私有 answerSpec、未揭示的答案/提示或未来题目的解法。不是把整个 ProblemSpec 塞进浏览器再用 CSS 隐藏答案。示范题通过显式 DEMO 投影允许展示已算出的解法。

数值正确性与表示/解释质量分开记录。交换因子、采用心算或不同正确解法，不应因不符合示范模板而判数学错误。某题明确检查标注或建模时，可以提示该子任务尚未完成，而不是覆盖正确数值结果。

## 4. Tutor 权限与响应

每次辅导使用当前 lesson/version、step/item instance、学生刚才的输入、可信画面状态、已揭示帮助和有限近期记录。AI 可选择本目标内许可的解释、表示和补救分支，可问一个澄清问题；不能变更服务端数量、答案、长期课程路径或直接写 Evidence/Mastery。

响应分为：简短说明、一个可执行下一动作、必要时一个问题。模型不得声称已显示未成功渲染的题卡或已记录失败的提交。教材或上传内容当作数据，不能通过其中的指令开启工具或改变权限。

语音识别结果先作为可编辑输入；听错和未识别不算数学错误。开放解释的反馈按 rubric 提示，模型不确定时记 unverified 并提供结构化检查，不用儿童用词、沉默、速度推断智力、情绪或能力。

## 5. 错误与补救分支

正确：解释对应关系的一句反馈后前进。空输入/格式问题：中性提示，不记 INCORRECT。典型错误值只触发可能性探查，不能单凭一个数字确认永久错因。非典型错误使用对应题目的通用 H1，再必要时问一个澄清问题。

每题最多两次失败的独立重试后，提供“换种讲法”“看示范”“稍后继续”；仍可主动重试，但不自动无限循环。两次是设计默认，待试学调整，并非学习规律。

H1 聚焦已知与问题；H2 给图示或一个中间步骤；H3 完整演示当前题。任何 H1/H2/H3 都记为该题已辅助。H3 后用新的参数/问法检查，不把刚看过答案的重答计为独立成功。

系统可以先用中性示范继续帮助，不等待家长确认错误分类。需要家长介入的是无法解决的内容歧义、识别问题或学生明确请求，不是每条纠错路径的固定审批。

## 6. 数学表示契约

第一批只需要可信组件，不需要通用可执行内容：

- BASE_TEN：unit=1、ten=10、hundred=100；交换保持总值，不在交换动作中同时加/减数量。值限制在课例范围；交换前后都能读出值。
- EQUAL_GROUPS：groupCount、groupSize、total 三者满足乘积关系。允许手动暂时不均分，提交时检查总数守恒和各组数量；不把临时操作中间态当作错误提交。
- BAR_MODEL：段、标签、未知量和关系由数学结构生成；不依据像素长度评分。初始未知条使用示意长度且不暴露隐含答案，只有已解出的示范可按比例。旋转、上下交换两条但关系等价时可接受。
- NUMBER_LINE 可作为 A1 的第二表示；比例一致，落点按数值而非拖动像素判定。

每个表示必须有 plain-text equivalent、静态 fallback 与学生动作定义。渲染失败直接显示等价数量关系，不能把空白画布当作成功交付。

## 7. 作答、恢复与完成

概念记录：lesson/version、stepId、itemInstanceId、服务端判定的 answer outcome、hint/demonstration events、解释验证状态和服务器时间。实际表结构由 B 决定，不在 A 创建第二套 Attempt 真值。新教学活动不强行冒充旧 PRACTICE/REVIEW；B 须明确兼容层。

同一提交使用稳定 requestId；重连先查询该提交结果，再决定重发，避免重复计数。保存最近确认步骤与本地草稿时必须区分“已同步”和“仅在本机”。离线可继续看已加载内容，作答等待同步，不展示伪造的服务端成绩。

恢复固定到原 Pack version、原题实例、帮助级别和最新已确认结果。暂停计时，不把离开时间计入学习。后台发布新内容不在当前题中途切版本；旧版确需撤回时说明原因并保留记录。切换学生必须清除前一学生缓存和草稿。

“本节结束”可由已走完计划或主动暂停产生不同摘要；不要求必须全对才可退出。课堂完成、独立检查结果和整个 objective 的 Mastery 三者独立。

## 8. 内容制作与发布

大纲 → 教学脚本/锚定题 → 数学检查 → 教学自审/必要的专业审校 → 课堂预览 → 试学记录 → 发布。检查是按课/单元组织，不为每个编辑动作加审批。

内容预览要使用学生端同一 renderer；编辑侧可见答案，学生投影不可见。来源目录和 citation locator 由真实记录提供，AI 不能自行构造可点击页码。原创课例不显示“教材原题”。

## 9. 本设计不替代哪些事

A 不验证浏览器布局、实际语音服务、真实模型对话质量或儿童学习效果。A 不决定新的长期 Mastery 阈值、不自动修改原证据规则。B 实施前要用本包的真实输入输出完成接口和政策兼容计划。
